# Reviewer trial: GPT-6 Astra (medium) and GPT-6.1 Sol (high, xhigh)

- **Date:** 2026-10-22
- **Asked by:** the owner, to decide the reviewer pinned in `.conclave/reviewers.toml` for Claude-written work.
- **Outcome:** the pin moves to GPT-6.1 Sol at xhigh (`[reviewers.sol]`, owner decision the same day). Codex accepts `low` to `xhigh`; there is no `max`, and `scripts/review-dispatch.py` allows the same four.

## How it was run

One review prompt, run three times in parallel against the same candidate, with nothing else different:

- **Prompt:** the `D06 T05 §20` audit round 4 prompt for `D01 T01 §7` (lossless stream filters), generated by the same helper that writes every audit round, with all six lenses.
- **Candidate:** `50af32b` on `main`, after three recorded rounds had already fixed six findings in that area.
- **Command:** `codex exec -m <model> -c model_reasoning_effort=<effort> --sandbox read-only --ephemeral --skip-git-repo-check -`, the dispatcher's own argv, prompt on stdin, codex-cli 0.163.0.
- **Not recorded as a round.** These runs sit outside `docs/reviews/`; the official round 4 runs through the dispatcher on the new pin.

## Results

| Reviewer | Effort | Wall time | Tokens | Verdict | Distinct findings |
| -------- | ------ | --------: | -----: | ------- | ----------------: |
| GPT-6 Astra | medium | 197 s | 91,771 | needs-attention, P2 | 2 of 3 |
| GPT-6.1 Sol | high | 239 s | 148,131 | needs-attention, P2 | 2 of 3 |
| GPT-6.1 Sol | xhigh | 460 s | 170,010 | needs-attention, P1 | 3 of 3 |

The three distinct findings across all runs, each verified against the source before this report:

| Finding | Astra medium | Sol high | Sol xhigh |
| ------- | :----------: | :------: | :-------: |
| A. Incomplete single-symbol Huffman tree accepted at any code length | yes (literal table, P2) | no | yes (distance table, P1) |
| B. Object-stream decoding passes no resolver | no | yes (P2) | yes (P2) |
| C. Round 3 code comment says RFC 1951 allows HLIT 288 (it caps at 286) | yes (P3) | yes (P3) | yes (P3) |

Verification:

- **A:** `src/pdf/filters.cpp:213` allows an incomplete tree whenever it has one symbol, without requiring a one-bit code. Python's zlib rejects both reviewers' vectors (`invalid literal/lengths set`, `invalid distances set`).
- **B:** `src/pdf/xref.cpp:1696` and `src/pdf/document.cpp:1575` call `decode_stream` without the resolver that the round 1 and 2 fixes rely on.
- **C:** the comment was mine, and RFC 1951 section 3.2.7 caps HLIT at 286.

## Side by side

**Astra medium vs Sol high.** Each found two of the three, and they found different things beyond the shared comment error. Astra found the Huffman tree defect and even executed its vector through zlib; Sol high found the object-stream integration gap and missed the Huffman defect. Sol high used 61% more tokens and 21% more time for the same count. On this sample, high effort is not a clear step up from Astra at medium.

**Astra medium vs Sol xhigh.** Sol xhigh found everything Astra found plus the object-stream gap, and it rated the Huffman defect on the distance table, where it is reachable through ordinary streams, as P1. It took 2.3 times the wall time and 1.9 times the tokens. Its findings came with exact `file:line` anchors, a constructed vector checked against zlib, and a spec citation for each.

**Sol high vs Sol xhigh.** Same model; xhigh found the one defect high missed (the Huffman tree) and kept everything high found. xhigh nearly doubled the wall time (239 s to 460 s) for 15% more tokens, so the extra cost is mostly time.

## Recommendation and limits

- **Use Sol at xhigh.** It was the only configuration to find every real defect, and missed defects cost more than four extra minutes per round. Sol at high does not justify itself over Astra at medium on this evidence.
- **One sample only.** The candidate had already been through three rounds, which favours whichever reviewer looks deepest, so a fresh candidate could rank them differently.
- **Watch the next rounds.** The next five Sol xhigh rounds in `docs/reviews/` are the check: if it repeatedly finds nothing that Astra-era rounds would have missed, or rounds run past the dispatcher's timeout, revisit the pin.
- **The ASan check didn't hold in the reviewers' sandbox.** All three runs reported `ASan=disabled` from the binary on disk, because the last full build was the non-ASan `build.cmd`. That reflects the build order, not the reviewers. The ASan checkpoint is rerun in the gates.
