Evidence: [interpreter.cpp](/R:/GitHub/Recto/src/pdf/interpreter.cpp:40), [SeparationAndDeviceN test](/R:/GitHub/Recto/tests/recto-tests/pdf_interpreter_tests.cpp:1839).

2. **Present: Palette and tint conversion primitives.** The candidate converts Indexed entries and Separation or DeviceN tints through their base or alternate spaces, including image sample rows. Evidence: [color.cpp](/R:/GitHub/Recto/src/pdf/color.cpp:713), [IndexedColors test](/R:/GitHub/Recto/tests/recto-tests/pdf_interpreter_tests.cpp:1771), [SpecialSpaceSamples test](/R:/GitHub/Recto/tests/recto-tests/pdf_interpreter_tests.cpp:1952).

3. **Present: Bounded parsing and specified recovery for several damaged inputs.** Sample tables and calculator programs have limits, and tests cover short tables, calculator failures and other refusals. Evidence: [function.cpp](/R:/GitHub/Recto/src/pdf/function.cpp:264), [Functions test](/R:/GitHub/Recto/tests/recto-tests/pdf_interpreter_tests.cpp:1465).

4. **Missing-in-scope: Consistent interpolation for functions with more than eight inputs.** [function.cpp](/R:/GitHub/Recto/src/pdf/function.cpp:727) chooses multilinear or simplex interpolation by the number of *fractional* coordinates, although the contract chooses by the function’s input count. For a nine-input table whose value is one when the first two sample coordinates are one and zero otherwise, the first eight inputs at 0.5 yield 0.25 when the ninth is exactly zero, but approach 0.5 as it rises above zero. A tiny tint change can therefore cause a visible colour jump. Add a regression at and on both sides of the boundary.

5. **Missing-in-scope: Cubic interpolation for large one-input sampled functions.** [function.cpp](/R:/GitHub/Recto/src/pdf/function.cpp:339) silently uses linear interpolation when `/Order 3` has more than 65,536 samples, even when the table fits the 16 MiB limit. The section promises a natural cubic spline for one input. Test a 65,537-sample table at an interior point where cubic and linear results differ.

6. **Missing-in-scope: Refusal of invalid sampled interpolation orders.** [function.cpp](/R:/GitHub/Recto/src/pdf/function.cpp:322) reads `/Order` but treats values other than 3 as linear, including invalid values such as 2. [Adobe’s PDF 1.7 reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.7old.pdf) specifies orders 1 and 3. A received malformed PDF should produce the section’s typed damage diagnostic, with a regression test.

7. **Missing-in-scope: Correct calculator integer boundaries.** [function.cpp](/R:/GitHub/Recto/src/pdf/function.cpp:507) classifies `-2147483648` as a real, and [the `cvi` implementation](/R:/GitHub/Recto/src/pdf/function.cpp:893) rejects that value. Integer-only operations such as `bitshift` then fail and substitute the range-low colour. Test the minimum signed integer as both a literal and a `cvi` result through a tint transform. [Adobe’s PostScript reference](https://www.adobe.com/jp/print/postscript/pdfs/PLRM.pdf) specifies integer operands for `bitshift`.

8. **Missing-out-of-scope: Actual text, image, stencil and Form rendering.** A reader still needs these colours applied to document content, including `/None` suppressing marks. These consumers and their tests are explicitly unfinished in [D01 T02 §4](/R:/GitHub/Recto/todo/01-engine/TODO-02-actor-and-render.md:217), owned by domain 01. The row-conversion tests do not establish that an opened PDF displays those objects correctly.

9. **Missing-out-of-scope: Responsive cancellation during expensive colour conversion.** A large DeviceN image can evaluate a long calculator program for every pixel in [color.cpp](/R:/GitHub/Recto/src/pdf/color.cpp:750); this loop has no cancellation input. Test cancellation during such a row against the planned sub-10 ms target, without publishing partial output.

10. **Missing-out-of-scope: End-to-end colour regression images.** The candidate has component and display-list tests, but no rendered-page golden proving that spot-colour paths, text, images and `/None` survive the complete pipeline. Domain 06 owns the planned [golden render harness](/R:/GitHub/Recto/todo/06-quality/TODO-01-corpus-and-suites.md:61). Add representative PDFs and independently checked expected pixels when the downstream renderer exists.
