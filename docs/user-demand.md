# User demand ledger

Every recurring request for Recto, and its answer: **planned** (TODO sections will build it as asked), **decided** (a scope decision: the named sections build a stated, narrower form, which may not be built yet) or **not planned** (with the decision and the reason). Recto is in early development, so planned and decided rows describe intent, not shipped features. Nothing someone asks for repeatedly is left without an answer. Before you open a feature request, check here and in the [open issues](https://github.com/rizonesoft/Recto/issues?q=is%3Aissue+is%3Aopen); if your request is listed as not planned and you have a case the reason does not cover, say so in a new request and link this row.

Maintainers review this ledger before every release (`docs/support/triage.md`), and `python scripts/check-user-demand.py` checks it on every change (CI): every TODO reference in any cell resolves, every decision exists in the foundation plan, every parity row without a TODO owner has a row here, and no row is dated in the future or before the newest release. Before a release, `--release` also requires every row to have been reviewed in the last 14 days.

Evidence names the source of the request: a Recto issue (`#N`), or a row of [`docs/acrobat-parity.md`](acrobat-parity.md) (`parity: <tool>`). Decisions `D<n>` are in [`docs/plans/2026-10-13-recto-foundation.md`](plans/2026-10-13-recto-foundation.md).
