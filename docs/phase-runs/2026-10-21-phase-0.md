## Lessons

- A hand-written heading starting with `## Round` in a findings file makes `review-dispatch.py --record` refuse the file; name notes `## Fixes after round N`.
- Codex's elevated Windows sandbox fails its setup refresh (`os error 32`) while any other Codex session runs `node_repl.exe`; this machine now uses `[windows] sandbox = "unelevated"`.
- A stdlib YAML reader must be an allow-list of what it loads exactly as YAML 1.1 does; refusal lists leak shape after shape.
- A CI concurrency change has to be read together with the trigger's path filters: removing cancellation multiplies whatever the triggers let through.
- A helper that writes a file must write a temporary file and replace it (AGENTS.md): a failed in-place write truncated `build/build.ps1` during the D06 T05 §3 audit; it was restored from `HEAD` before any commit.
- A note heading in a findings file must not start with `## Round`: the dispatcher's reader treats it as a malformed round and the stamp gate refuses the file (caught on D06 T05 §5; use `## Fixes after round N` or `## Stop after round N`).
- A build-script change must be proven on the CI image, not only locally: the D06 T05 §3 `vswhere -requires` list named components GitHub's `windows-latest` image does not register, and every CI build failed from `59902fc` to `07f3563`.
- Parsers that kept leaking edge cases (D06 T05 §5: checklist items, deferral markers, XREFs, severity) were closed by allow-lists and by reading the authoritative record (the dispatcher's own `read_rounds`, the reviewer's declared `HIGHEST` line), not by patching one spelling at a time.
