1. **P1**, `tests/recto-tests/ui_project_tests.cpp:171`: Macro-based includes bypass `IncludeBoundary`. In a `src/core` source, use:

   ```cpp
   #define UI_HEADER "../ui/include/recto/ui/ui.h"

   ```

   The compiler includes the forbidden header, but the regex extracts no target. Confirmed using Clang-cl `/Zs` and the candidate’s regex. Macro replacement in include directives is [standard C++ behavior](https://eel.is/c++draft/cpp.include).

The binary reader preserves those bytes, so the anchored regex misses the directive. Clang-cl accepted this input; the source-derived probe found zero targets. [MSVC also recognizes BOM-encoded source](https://learn.microsoft.com/en-us/cpp/build/reference/utf-8-set-source-and-executable-character-sets-to-utf-8).

3. **P1**, `tests/recto-tests/ui_project_tests.cpp:121`: `logical_source` mishandles raw strings and can erase subsequent executable source from both guards. Reproduce in an engine source with:


## Fixes for round 3 (implementing session)

Round 2 re-reported round 1 because its prompt named the old commit (see the note above). Round 3 reviewed ac6da59 and found three more ways to hide an include from a text scan: a macro operand, a UTF-8 BOM and a raw string literal. Fixed in the next commit: `#include MACRO` is refused outright inside the guarded modules, the BOM is dropped before lexing, and raw string bodies are opaque to the comment stripper; each shape is planted in `Ui.Project.IncludeBoundary`. Decision: the text scan is the second wall. The first wall is the build itself (`recto-ui` has no engine directory on its include path and the engine projects have no `src/ui` one), so a scan bypass is not an architecture breach; further preprocessor-level evasions (for example `__has_include` tricks) are not chased and are recorded here as accepted P3 residue.
