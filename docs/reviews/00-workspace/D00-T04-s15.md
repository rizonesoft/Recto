2. **P2: Consumed token allocations survive clearing the lookahead.** `src/pdf/lexer.cpp:301` removes consumed tokens from the active count without releasing their storage. However, `clear_lookahead()` at line 173 clears only active inline slots. Reproduce by parsing `[1 2 (<64 MiB of a>)]`: integer lookahead puts the string in slot 1, consuming it resets the head to slot 0, and subsequent ordinary tokens reuse slot 0. Release the parsed value and call `seek()`; slot 1 still owns the 64 MiB allocation. Accepted strings can reach 256 MiB, leaving substantial unnecessary memory held during subsequent parsing and causing avoidable allocation failures under memory pressure. Clear retired slots once their documented pointer lifetime ends, including during resets, and cover this sequence with a regression test.
