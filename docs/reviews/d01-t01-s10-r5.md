## Findings

1. **`major` — `ParsedDest::fit_mode` copies an unrestricted `std::string` name without validating standard PDF destination fit modes (`src/pdf/document.h`, `src/pdf/document.cpp`):**
   - `parse_dest_array` copied `fit_name` into `std::string fit_mode` before validating that it is one of the 8 standard PDF destination fit modes (`XYZ`, `Fit`, `FitH`, `FitV`, `FitR`, `FitB`, `FitBH`, `FitBV` per ISO 32000-1 Table 151), allowing a shared destination array with a 64 KiB `/FitMode` name and 2,048 destination names to allocate 186 MB of heap storage outside `sizeof(ParsedDest)`.
   - **Resolution:** Changed `ParsedDest::fit_mode` from `std::string` to `std::string_view` backed by static string literals for the 8 valid ISO 32000-1 Table 151 fit modes (`"XYZ"`, `"Fit"`, `"FitH"`, `"FitV"`, `"FitR"`, `"FitB"`, `"FitBH"`, `"FitBV"`), rejecting unrecognized fit-mode names (`out.valid = false`), and added `static_assert(std::is_trivially_copyable_v<ParsedDest>)` so `ParsedDest` is guaranteed to own zero dynamic heap allocations. Added regression coverage in `PdfDocument.OutlinesAndNamedDests` (`tests/recto-tests/pdf_document_tests.cpp`) testing 2,048 destination names sharing a destination array with a 64 KiB fit-mode name and asserting `< 32 MiB` working-set growth.
