## Findings

1. **`major` — Shared `/Annots` link URIs and action payloads cause unbounded allocation amplification (`src/pdf/document.cpp`):**
   - When 2,048 distinct `/Subtype /Link` annotations referenced a single shared `/A << /S /URI /URI (...) >>` action object containing a 64 KiB URI string, `load_document_structure()` resolved the shared action object 2,048 times and retained 2,048 separate 64 KiB `std::string` copies across `page_rec.links` (reaching 524 MB working set on a 285 KB PDF).
   - **Resolution:** Added indirect-action caching (`parsed_action_obj_cache` keyed by indirect action object number) so shared `/A` dictionaries are resolved and validated at most once, bounded individual and aggregate retained strings and object counts across `/Info` / XMP metadata (`kMaxMetadataFieldBytes = 64 KiB`, `kMaxMetadataStreamBytes = 4 MiB`), `/Outlines` (`kMaxOutlineStringBytes = 4 KiB`, `kMaxTotalOutlineBytes = 8 MiB`, plus cursor-based outline traversal), `/Annots` links (`kMaxLinkUriBytes = 8 KiB`, `kMaxTotalDocumentLinks = 65,536`, `kMaxTotalLinkBytes = 8 MiB`), and `/Resources /Font` (`kMaxFontStringBytes = 1 KiB`, `kMaxTotalFonts = 4,096`, `kMaxTotalFontBytes = 2 MiB`), returning typed `ErrorCode::DamagedFormat` errors whenever a hostile document exceeds any retention budget. Added regression coverage in `PdfDocument.LinksAndRefusedActions` (`tests/recto-tests/pdf_document_tests.cpp`) testing 2,048 distinct link annotations referencing a shared 64 KiB `/URI` action and asserting typed rejection with `< 32 MiB` working-set growth.
