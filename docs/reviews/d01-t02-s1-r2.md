## Findings

1. **P2 (`src/pdf/display_list.cpp:747`): Resource budgets exclude substantial retained and temporary allocations.**
   - `current_pool_bytes()` excludes clip edges, saved state stack copies, and geometry scratch; `save_state()` copies active clips; all-pairs intersection can perform unbudgeted quadratic work.
   - **Fix:** Share immutable `ClipRegion` instances via `std::shared_ptr<const ClipRegion>`, account for retained clip/state-stack bytes and scratch geometry bytes against `max_total_bytes` before allocation, and enforce `max_clip_depth` and `max_geometry_work_ops` in `DisplayListLimits`. Add small-budget tests exercising repeated clips and saved states.

2. **P2 (`src/pdf/display_list.cpp:1372`): Allocation failures silently corrupt bounds or leave partially committed operations.**
   - `accumulate_clipped_region` falls back to `window` on `bad_alloc`, `accumulate_clipped_segment` drops ink on `bad_alloc`, and `draw_path` appends its command before computing bounds.
   - **Fix:** Return `PdfResult<void>` from all bounds accumulation helpers without fallback approximation, compute bounds and reserve command capacity before committing state/command mutations, latch any non-recoverable failure, and add deterministic allocation-failure injection tests.

3. **P2 (`src/pdf/display_list.cpp:2132`): Failed shared-pointer allocation can recreate the stale-bounds sealing bug.**
   - Constructing `DisplayList` moves pools before allocating the `shared_ptr` control block; if control-block allocation fails, a retry can publish an empty list with stale bounds.
   - **Fix:** Allocate the `shared_ptr` control block transactionally (and/or permanently latch failure before moving storage) and test injected allocation failure in `finish()` followed by a retry.

4. **P2 (`src/pdf/display_list.cpp:345`): Fixed polygon sampling cannot provide exact curved clipped bounds.**
   - Fixed 32/48-step sampling of cubic Beziers and round caps/joins intersects chords rather than the true curve when clipped between sample vertices.
   - **Fix:** Split cubic Beziers and round caps/joins at their exact intersections with active clip edges (cubic root finding via derivative split + bisection to `1e-13`, and analytic trigonometric intersection for circular arcs) plus adaptive flatness refinement so curved clipped bounds are exact. Add tests with narrow clips intersecting a cubic Bezier and a round cap between sample vertices.

5. **P2 (`src/pdf/display_list.cpp:1058`): Dash patterns are recorded but ignored by bounds tracking.**
   - `TrackingState` does not retain the active dash array/phase, and `draw_path()` strokes the entire continuous path even over dash gaps.
   - **Fix:** Track saved/restored `dash_array` and `dash_phase` in `TrackingState` and decompose subpaths into painted dash segments (supporting phase offset and odd-length pattern doubling per ISO 32000-1 §8.4.3.6) before stroking and clipping. Add phase, odd-length pattern, and gap-only clip tests.

6. **P2 (`src/pdf/display_list.cpp:1985`): Combining glyph bounds before clipping invents ink between glyphs.**
   - `draw_glyph_run()` unions all glyph rectangles into one run box before clipping, so a clip restricted to the inter-glyph gap falsely reports content bounds.
   - **Fix:** Clip each visible glyph's ink rectangle (or Type 3 sub-list bounds) individually against the active clip stack before unioning into `content_bounds_pt_`. Add a two-glyph run test with a clip restricted to the inter-glyph gap.

7. **P2 (`src/pdf/display_list.cpp:2093`): Independent bitmap and mask visibility checks do not establish visible combined ink.**
   - Disjoint non-transparent pixels in `bitmap` and `soft_mask` (e.g. `[255, 0]` and `[0, 255]`) or transparent image margins still contribute the full `[0, 1] x [0, 1]` image rectangle to `content_bounds_pt_`.
   - **Fix:** Compute effective non-transparent pixel coverage rectangles in unit image space (after applying `soft_mask` alpha where present) and clip each coverage rectangle against the active clip stack. Add disjoint-alpha and transparent-margin tests.

8. **P2 (`src/pdf/display_list.cpp:1491`): Finite source values can overflow during geometry transformation without rejection.**
   - Finite coordinates combined with a large finite CTM (e.g. `1e308`) can overflow to `+-Inf`/`NaN` during transformation in `push_clip_path`, `draw_path`, `draw_glyph_run`, or `draw_image`.
   - **Fix:** Validate that all transformed path, clip, stroke-offset, glyph, and image coordinates remain finite before recording commands or mutating state, returning `ErrorCode::DamagedFormat` on overflow. Add finite-input overflow tests for paths, clips, glyphs, and images.
