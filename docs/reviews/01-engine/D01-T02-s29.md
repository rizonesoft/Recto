5. **missing-in-scope, P1:** Numeric safety does not extend through transformations and all arithmetic consumers. `Builder::count_op` checks input coordinates, but `place` can overflow finite coordinates through a finite, enormous `/FontMatrix`; transformed points and advances are returned without finite checks (`src/pdf/font_charstrings.cpp:73`, `:125`, `:905`, `:1918`). 6. **missing-in-scope, P1:** CFF parsing lacks an aggregate allocation/work bound for expanded metadata. `sid_string` copies an arbitrary-length String INDEX entry (`src/pdf/font_charstrings.cpp:1119`), and charset construction repeats that copy per glyph (`:1296`). A crafted small font can repeatedly reference a megabyte string and request tens of gigabytes of allocations despite the 64 MiB input limit. Bound glyph-name lengths and cumulative parsed storage before allocation; test repeated oversized SIDs and shared private-data expansion. Catching `bad_alloc` after memory pressure is insufficient.

7. **missing-in-scope, P2:** Malformed glyph programs can report success. Both interpreters accept end-of-buffer without the required termination and accept top-level `return` (`src/pdf/font_charstrings.cpp:715`, `:864`, `:1653`, `:1680`). Type 2 path operators discard excess operands, for example an odd `rlineto` operand at `:1555`; Type 1 `pop` invents zero on an empty auxiliary stack at `:841`. Require termination, operand-arity and stack-state validation, with failing-result assertions. Adobe specifies explicit Type 2 termination, including termination reached through a subroutine. [Adobe TN 5177](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)

8. **missing-in-scope, P2:** Legacy CFF `dotsection` is rejected. `Type2Run::escape` has no case for escape opcode 0 and returns `DamagedFormat` (`src/pdf/font_charstrings.cpp:1691`, `:1851`). Adobe explicitly documents this compatibility operator as a no-op. Accept it without changing outlines or widths and add a regression fixture. [Adobe TN 5177, Appendix C](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf)
