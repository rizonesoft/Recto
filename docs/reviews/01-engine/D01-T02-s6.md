### adversarial: needs-attention

1. **P1: Image sampling performs out-of-range floating-to-integer conversions.** `src/pdf/rasterizer.cpp:940` converts inverse-transformed coordinates to `int64_t` before clamping them. `sampler_for` rejects only zero/nonfinite determinants, so finite, near-singular matrices reach these casts.

   **Reproduce:** Open a PDF with a 200-point page and a 1×1 opaque image painted under `100 100 0.00000000000000000001 0.00000000000000000002 0 0 cm`. Render at scale 1. The image’s bounding rectangle triggers sampling before its geometric mask applies. At device pixel `(0,100)`, the inverse sample coordinate is approximately `-9.9e21`, outside `int64_t`. This produces **undefined behaviour from document input**. Clamp in floating point and validate inverse coefficients before conversion.

### integration: needs-attention

2. **P1: The bounded image cache retains gigabytes of unaccounted source images.** `src/pdf/rasterizer.cpp:889` retains a strong `source` reference in every cache entry, but line 891 charges only the reduced pixel vector. Releasing a page’s DisplayList therefore cannot release its decoded images while these entries survive.

   **Reproduce:** Render successive PDF pages on one worker, each containing a distinct 4096×4096 image displayed at 64×64 pixels. After 64 pages, the cache retains **4 GiB of source pixels while accounting for only 1 MiB** of reductions, far below its 256 MiB eviction threshold. Compressed uniform images make this reachable from a small document. Account for retained source storage or avoid owning it solely to stabilize cache keys.

### source-defect: needs-attention

3. **P1: Dashed hairlines have incorrect lengths under anisotropic transforms.** `src/pdf/rasterizer.cpp:629` uses `sqrt(abs(det))` to scale every hairline dash in device space. Dash lengths must follow the path’s user-space geometry, independently of the one-device-pixel stroke width. [ISO 32000-1 §8.4.3.6](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf)

   **Reproduce:** Open a valid PDF containing `q 1 0 0 4 0 0 cm 0 w [10 10] 0 d 10 10 m 90 10 l S Q`, rendered at scale 1. Its horizontal dash and gap lengths should each be 10 pixels; this implementation produces 20 pixels. A vertical line instead needs 40-pixel lengths but also receives 20. This is **wrong output on a valid file**. Split dashes in user space before widening the resulting hairline segments in device space.

### plan-delivery: needs-attention

Finding 3 leaves the checked “dashes in user space” requirement incomplete. `StrokeAndAlpha` tests anisotropic hairlines and dashed strokes separately, so it does not detect their broken combination.

These findings are based on source tracing and an executed numerical check of the inverse-transform calculation. I did not run the rasterizer or ASan tests. No files were modified.
