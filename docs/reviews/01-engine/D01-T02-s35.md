1. **P1, plan, lines 1037 and 1044–1048:** Failure handling and resource limits are incomplete. Neither API declares a typed result, an output-size budget, or what happens to `out` after failure. Depth alone does not bound allocation when escaping large strings or copying streams. Specify `PdfResult` returns, checked output growth, allocation-failure translation, and append/rollback semantics. Add tests for the depth boundary, oversized output and failure after partial serialization, asserting the error and unchanged input/output. The current success-only checkpoints would pass without these protections.

2. **P1, plan, lines 1044–1045:** The stream representation contract is missing. `PdfStream` contains both `raw_bytes` and optional `decoded_bytes`; `payload_bytes()` prefers the decoded cache. Serializing that cache while retaining `/Filter` would corrupt an ordinary compressed stream after it has been decoded. Require serialization of encoded `raw_bytes`, preservation of `/Filter` and `/DecodeParms`, and `/Length` calculated from the emitted bytes without mutating the input. Test a filtered stream with its decoded cache populated and verify both encoded bytes and decoded content after reopening. Define semantic round-trip comparison explicitly: `PdfStream::operator==` includes the cache and dictionary, so cache removal and replacing an indirect `/Length` prevent unconditional object equality. [ISO 32000-1 §7.3.8](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf?from=20423&from_column=20423)

3. **P2, plan, line 1045:** Reopening and comparing stream bytes does not prove correct stream framing or `/Length`. The existing parser scans for `endstream` when `/Length` is missing or wrong, so malformed serializer output can pass this checkpoint. Add direct assertions for the emitted length and delimiters, including empty streams, binary payloads containing `endstream`, and payloads ending in CR/LF. Assert indirect object number/generation and non-stream values too; checking only stream bytes leaves the rest of `serialize_indirect` unproven.
