1. **P1, lines 481–494:** No checkpoint verifies the delivered pixels. A worker that fetches the correct list but returns a blank or incorrectly transformed buffer could satisfy the specified scheduling tests. Add an actual-PDF test comparing delivered dimensions, stride and BGRA pixels against direct rasterization, covering tile offsets, rotation and zoom.

2. **P1, lines 470–471 and 489–490:** Scheduler destruction joins workers but does not define how outstanding actor callbacks become safe before scheduler state is destroyed. Closing a view while its page is compiling exercises this path. Specify callback lifetime ownership and shutdown synchronization; test destruction with a held actor fetch, then release that fetch and verify exactly one cancellation, no later delivery and no invalid access under ASan.

3. **P1, lines 471 and 489:** The new callback API promises answers on the actor thread without defining admission failures or requests submitted after `close()`. The shipped actor rejects a full queue immediately, and a closed actor has no thread left to execute callbacks. Define an explicit synchronous admission result or a documented callback-thread exception for these paths. Test queue saturation, allocation failure and submission after closure without losing a tile completion.

4. **P2, lines 464 and 486:** `PriorityOrdering` checks only current-page completion before thumbnails. It cannot prove the middle tiers, FIFO ties or reprioritization of surviving requests; concurrent completion order also need not equal dequeue order. Assert dequeue/start order with controlled workers for all four tiers, FIFO ties and a viewport update that promotes an existing queued request.

5. **P2, lines 458, 467 and 484:** The unsigned default calculation underflows when `hardware_concurrency()` returns 1, selecting eight workers instead of two. The options contract also calls zero both the default and an invalid value outside `1..16`. Specify saturating subtraction, explicitly accept zero, and test reported core counts 0, 1, 2 and larger values plus override boundaries.

6. **P2, lines 467 and 484:** Worker startup failures have no defined outcome or proof. Thread creation, COM initialization or `Rasterizer::create()` can fail on a real Windows host, including after some workers have started. Require typed creation failure, cleanup and joining of partially started workers, and a test proving no unusable scheduler or leaked worker survives.

7. **P2, line 470:** The texture-upload handoff contradicts its named consumer and governing contract. Foundation §4.5 and `D02 T02 §3` require worker-side texture creation; this line assigns creation to the presentation thread and references `D02 T03`. Correct the reference and preserve worker-side upload, or explicitly reconcile the governing plan and consumer section before building.
