1. **P1, plan, line 1073:** The object-encryption contract omits crypt-filter selection beyond `Identity`: independent `/StrF` and `/StmF`, `/EFF` for embedded files, and named per-stream `/Crypt` overrides. Unlike `decrypt_object_values`, the proposed API also accepts no resolver for indirect `/Type`, `/Filter` or `/DecodeParms`. Add the selection rules, a resolver or an explicitly owned normalization prerequisite, typed refusal for unknown filters, and tests with differing string, stream and attachment filters plus indirect parameters. Otherwise legitimate encrypted PDFs can be saved with payloads encrypted under the wrong method. These distinctions are defined in [ISO 32000-1 §7.6](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf).

2. **P2, plan, lines 1065 and 1073:** “Leaves the value unchanged on failure” has no executable proof. Recursive encryption can successfully replace earlier strings before allocation, randomness generation or encryption fails on a later value. Add failure-injection tests after partial traversal, asserting a typed error, unchanged complete input and handler state, and a successful retry. Include depth-limit refusal and allocation failure; ASan and successful round trips do not establish these guarantees.

3. **P2, plan, line 1072:** “Two encryptions of one string differ” is not qualified to AES. RC4 encryption with the same plaintext, object reference and authenticated key is deterministic, so a literal implementation cannot satisfy this gate for every listed method. Restrict the differing-output assertion to AESV2/AESV3, test fresh IVs for both strings and streams, and require deterministic expected ciphertext for RC4. See [ISO 32000-1 Algorithm 1](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf).

4. **P2, plan, lines 1072–1073 and 1076:** The tests do not require empty or block-boundary inputs, or independently checked ciphertext. This matters because the existing `decrypt_bytes` passes empty ciphertext through unchanged: an encryptor that incorrectly copies that shortcut would pass an empty round trip without producing the required AES IV and padded block. Add byte and object tests for lengths 0, 1, 15, 16 and 17, asserting ciphertext length and padding, including empty streams and strings. Add independent expected-output checks with a controlled test IV and nonzero object/generation numbers so shared key-derivation mistakes cannot pass through symmetric round trips.
