1. **P1, plan, lines 644, 646-647:** Always blending in sRGB discards the group’s `/CS`, including page groups without knockout. CMYK and calibrated-space transparency can therefore produce wrong colours. Preserve the blending space through recording and compositing, convert at group boundaries, and add pixel tests that distinguish correct group-space blending from early RGB conversion. See [ISO 32000-1, 11.3.4 and 11.6.6](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf).

2. **P1, plan, lines 644, 663, 668:** Nested soft-mask interpreters have no specified shared cycle detection, depth limit or aggregate allocation/work budget. Existing form guards belong to an individual interpreter, so they do not automatically protect this new recursion path. Add page-wide accounting across mask sub-lists, include their retained resources in `DisplayList::memory_bytes()`, and test cyclic `/G` references, combined form/mask nesting, budget exhaustion and allocation failure with typed outcomes.

3. **P1, plan, lines 648, 663-665:** Knockout support omits `/AIS` and the distinction between shape and opacity. Drawing at full alpha cannot recover shape correctly for every masked image or nested group. Add the graphics-state flag, separate shape accounting and save/restore behaviour, with overlapping knockout fixtures that distinguish `/AIS true` from `false`. See [ISO 32000-1, 11.6.4.3](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf?from=20423&from_column=20423).

4. **P1, plan, lines 648, 667:** “Object” is undefined for text compositing. The current rasterizer paints glyphs individually, while the plan adds neither `/TK` nor text-object boundaries. Overlapping translucent glyphs, including glyphs emitted by separate text-showing commands, can render incorrectly. Add text-knockout recording and replay, with pixel tests for both flag values across one `BT`/`ET` object. See [ISO 32000-1, 9.3.8](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf).

5. **P1, plan, lines 666-667:** Applying the current graphics-state soft mask to every object also applies it to images already carrying their own masks. Image masks override that graphics-state mask; multiplying both produces wrong coverage. Specify precedence and test an image with its own `/SMask` and another with `/Mask`, each under an active graphics-state mask. See [ISO 32000-1, 11.6.4.3](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf?from=20423&from_column=20423).

6. **P1, plan, line 668:** Flattening deeper groups changes isolation, knockout and group-opacity semantics while returning success. The proposed test proves only command count and a flag, with no consumer required to report degraded rendering. Preserve semantics or return an explicit typed refusal through the existing failure path. Test that exceeding the limit cannot yield an apparently successful, incorrectly composited tile.

7. **P1, plan, lines 645, 662-666, 675:** Several required behaviours lack discriminating tests. The soft-mask checkpoint requires only a luminosity gradient, so an implementation omitting Alpha masks, `/BC`, `/TR`, `/None`, mask save/restore or CTM capture could pass. Likewise, group-command read-back does not test rejected imbalance, and group probe pixels do not explicitly exercise non-isolated backdrop removal. Add targeted assertions for these cases, group-entry transparency reset and applying the caller’s transparency once at group exit.
