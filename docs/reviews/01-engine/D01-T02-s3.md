1. **P1, plan, line 191:** The entry point lacks an error and empty-page acceptance contract. Require a valid empty `DisplayList` for absent or empty `/Contents`, and propagation of typed failures from document access, decoding, parsing and builder operations without returning an apparently successful partial page. Add tests for a blank page, invalid page index, damaged content stream and builder failure. `OperatorDispatch` alone proves none of these.

2. **P1, plan, line 192:** `GraphicsStateStack` tests restoration but does not prove `cm` composition or its effect on recorded output. An implementation that ignores `cm`, reverses multiplication order or applies the transform twice could satisfy the stated checks. Add noncommuting translation/scale and rotation cases asserting transformed path bounds, clip placement and restoration after `Q`.

3. **P1, plan, line 195:** Clipping order is ambiguous, and the checkpoint only requires a clip and paint to exist. Specify that painting uses the previous clip, followed by intersection with the pending clip. Require `DrawPath` before `PushClipPath`, a `W S` case preserving the stroke outside the new boundary, and subsequent painting constrained by that boundary. Otherwise valid clipped vector artwork can lose ink while the test passes. [Adobe’s clipping semantics](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.3.pdf).

4. **P1, plan, lines 194-195:** Checking control points and fill/stroke flags does not prove painting semantics. Explicitly test closure for `s`, `b` and `b*`, distinguish nonzero from even-odd fills using a multi-subpath fixture, and assert that painting or `n` clears the path. The stated tests could pass with missing closing edges, identical `f`/`f*` behavior or stale geometry painted again.

5. **P2, plan, line 196:** Device-colour resource resolution is unspecified. Require `/ColorSpace << /C1 /DeviceRGB >>` followed by `/C1 cs` to behave like `/DeviceRGB cs`, including inherited resources and indirect values. Also explicitly assign `/DefaultGray`, `/DefaultRGB` and `/DefaultCMYK` substitution to §32 and add its acceptance tests there. Neither later colour section currently names those substitutions; treating unresolved names as black leaves valid documents incorrectly coloured. [ISO resource mappings](https://raw.githubusercontent.com/adobe/dc-acrobat-sdk-docs/master/docs/standards/pdfstandards/pdf/PDF32000_2008.pdf), [device-space substitution](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf).
