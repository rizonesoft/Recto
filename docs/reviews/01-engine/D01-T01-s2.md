### Round 1 (`553494dc31575af2a2f9b6db60d1266c085e28fd`) -- Verdict: `fixed`

- **Major 1 (`src/pdf/object.cpp:252, 289, 306`):** `clone_value_recursive` re-normalized stored `PdfName` instances through `PdfName(std::string_view)`, turning a decoded `"/A"` (from `/#2FA`) into `"A"` and collapsing dictionary entries when both keys existed.
  - **Fix (`53ed4ca`):** Added `PdfName::from_decoded(std::string_view)` and `PdfDict::get(const PdfName&)` / `PdfDict::erase(const PdfName&)`, and updated `clone_value_recursive` and `PdfDict::operator==` to preserve exact decoded `PdfName` bytes.
- **Minor 1 (`src/pdf/object.cpp:592`):** `PdfValue::deep_clone(size_t max_depth)` forwarded `max_depth` without clamping to `kMaxObjectCloneDepth` (`64`).
  - **Fix (`53ed4ca`):** Clamped `max_depth` via `std::min(max_depth, kMaxObjectCloneDepth)`.
- **Minor 2 (`src/pdf/object.cpp:665`):** The UTF-8 (`0xEF 0xBB 0xBF`) branch of `pdf_string_to_utf8` did not strip `0x1B ... 0x1B` language escape sequences like the UTF-16BE branch did.
  - **Fix (`53ed4ca`):** Stripped `0x1B ... 0x1B` language escape sequences in the UTF-8 branch of `pdf_string_to_utf8`.
- **Minor 3 (`src/pdf/object.cpp:678, 747`):** `pdf_string_to_utf8` and `utf8_to_pdf_string` caught allocation failures and returned an empty string indistinguishable from valid empty text.
  - **Fix (`53ed4ca`):** Changed `pdf_string_to_utf8`, `PdfString::to_utf8`, and `utf8_to_pdf_string` to return `PdfResult<std::string>` / `PdfResult<PdfString>`.
