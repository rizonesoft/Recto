## Writer note: what DirectWrite refuses (probe, 2026-10-24)

A one-off gtest probe (not kept) patched `tests/corpus/fonts/truetype-full-short-loca.ttf` and loaded each variant on this Windows 11 machine. DirectWrite accepted: a truncated `OS/2`, a `name` count past its data, wrong table checksums, an unsorted table directory, the `true` sfnt tag, a wrong `head` magic number, a `maxp` glyph count past `loca`, a bad `post` version, and (separately) no `cmap`, `OS/2`, `name` or `post` at all. It refused: a `cmap` header claiming more subtables than it holds (the `glyf` reader loaded it) and an `hhea.numberOfHMetrics` past the glyph count (refused by both until the reader clamped it). The section's fallback fixture and premise were corrected to these facts.

## Writer note: self-review before the completion review

Built in the main session (the operator's direction, 2026-10-24; an earlier writer-agent draft was set aside unread and is not in the tree). Findings from reading the diff against the three questions and the AGENTS.md failure modes, each fixed before the first commit:

- Diagnostics were recorded where errors were built, so a font DirectWrite rejected but the `glyf` reader loaded left a false damaged-font entry, and a failed fallback recorded twice. Errors are now recorded once, by the public functions (`recorded`), and `PdfFont.RefusedTrueTypeFallsBackToGlyfOutlines` checks the ring stays empty for a font that loads through the fallback.
- `E_INVALIDARG` counted as a font rejection at every DirectWrite step; it now counts only at the face (`PdfFont.LoaderFailuresAreTyped`, a rejection at the reference step is `InternalError`).
- The built-in in-memory loader keeps every program it was given for its own lifetime (`GetFileCount` counts all references ever created), so a process-wide one would hold the fonts of every document opened; replaced by the custom loader with a registry of weak references, and `PdfFont.InMemoryDirectWriteLoader` checks that a destroyed font leaves both the live stream count and the registry where they started.
- The plan's premise that DirectWrite refuses subsets missing `OS/2`, `name` or `post` was false (probe above); the fixture and section were corrected, and `numberOfHMetrics` past the glyph count is clamped rather than refused, since DirectWrite refuses it and the fallback can read it.
- `ResourceLimit` refusals lacked the closed reason `D01 T02 §23` requires; `FontProgramBytes`, `GlyphPoints`, `ComponentVisits` and `CompositeDepth` were appended to `RefusalReason` with descriptions, set on every font limit and asserted by `PdfFont.HostileFontProgramsRefused`.
- Contours that start on-curve emitted a zero-length `LineTo` back to the start before closing; the walk now visits each point once and lets the close draw the last line.
- Failure modes checked and holding: no throw escapes (every public function is `noexcept` and catches `std::bad_alloc`); no unbounded recursion (composite nesting is capped at 16, visits at 4,096, points at 65,535, counted before each expansion); every read is bounds-checked and `loca` is validated forwards once at load; the factory and loader are created under a mutex and the registry is read under its own; `LoadedFont` has only `const` members and no cache.
