## Writer note: what DirectWrite refuses (probe, 2026-10-24)

A one-off gtest probe (not kept) patched `tests/corpus/fonts/truetype-full-short-loca.ttf` and loaded each variant on this Windows 11 machine. DirectWrite accepted: a truncated `OS/2`, a `name` count past its data, wrong table checksums, an unsorted table directory, the `true` sfnt tag, a wrong `head` magic number, a `maxp` glyph count past `loca`, a bad `post` version, and (separately) no `cmap`, `OS/2`, `name` or `post` at all. It refused: a `cmap` header claiming more subtables than it holds (the `glyf` reader loaded it) and an `hhea.numberOfHMetrics` past the glyph count (refused by both until the reader clamped it). The section's fallback fixture and premise were corrected to these facts.

## Writer note: self-review before the completion review

Built in the main session (the operator's direction, 2026-10-24; an earlier writer-agent draft was set aside unread and is not in the tree). Findings from reading the diff against the three questions and the AGENTS.md failure modes, each fixed before the first commit:

- Diagnostics were recorded where errors were built, so a font DirectWrite rejected but the `glyf` reader loaded left a false damaged-font entry, and a failed fallback recorded twice. Errors are now recorded once, by the public functions (`recorded`), and `PdfFont.RefusedTrueTypeFallsBackToGlyfOutlines` checks the ring stays empty for a font that loads through the fallback.
- `E_INVALIDARG` counted as a font rejection at every DirectWrite step; it now counts only at the face (`PdfFont.LoaderFailuresAreTyped`, a rejection at the reference step is `InternalError`).
- The built-in in-memory loader keeps every program it was given for its own lifetime (`GetFileCount` counts all references ever created), so a process-wide one would hold the fonts of every document opened; replaced by the custom loader with a registry of weak references, and `PdfFont.InMemoryDirectWriteLoader` checks that a destroyed font leaves both the live stream count and the registry where they started.
- The plan's premise that DirectWrite refuses subsets missing `OS/2`, `name` or `post` was false (probe above); the fixture and section were corrected, and `numberOfHMetrics` past the glyph count is clamped rather than refused, since DirectWrite refuses it and the fallback can read it.
- `ResourceLimit` refusals lacked the closed reason `D01 T02 §23` requires; `FontProgramBytes`, `GlyphPoints`, `ComponentVisits` and `CompositeDepth` were appended to `RefusalReason` with descriptions, set on every font limit and asserted by `PdfFont.HostileFontProgramsRefused`.
- Contours that start on-curve emitted a zero-length `LineTo` back to the start before closing; the walk now visits each point once and lets the close draw the last line.
- Failure modes checked and holding: no throw escapes (every public function is `noexcept` and catches `std::bad_alloc`); no unbounded recursion (composite nesting is capped at 16, visits at 4,096, points at 65,535, counted before each expansion); every read is bounds-checked and `loca` is validated forwards once at load; the factory and loader are created under a mutex and the registry is read under its own; `LoadedFont` has only `const` members and no cache.

**Part 1: completeness**

1. **present:** In-memory TrueType and OpenType/CFF loading, shared DirectWrite factory, font ownership and release. Evidence: `src/pdf/font.cpp:309`, `src/pdf/font.cpp:947`, `src/pdf/font.cpp:1209`; `PdfFont.InMemoryDirectWriteLoader`.

2. **present:** Immutable query interface and concurrent access coverage. Evidence: `src/pdf/font.h:64`; `PdfFont.LoadedFontIsImmutable`. This proves the tested queries agree across two threads, not every possible font’s behaviour.

3. **present:** Basic advances, empty glyphs, negative bearings, overhangs, short/long `loca`, quadratic contours, scaled and point-attached composites. Evidence: `PdfFont.GlyphMetricsInTextSpace`, `PdfFont.RefusedTrueTypeFallsBackToGlyfOutlines`.

4. **missing-in-scope:** **Fallback positioning ignores horizontal side bearings.** `advance()` reads only widths (`src/pdf/font.cpp:1115`); fallback boxes and outlines use raw glyph coordinates (`src/pdf/font.cpp:1150`, `src/pdf/font.cpp:1191`). Neither reads the stored left side bearing, including trailing `hmtx` bearings. When `lsb != xMin`, this disagrees with the DirectWrite box’s origin at `leftSideBearing`. Add fixtures with unequal values and verify equivalent origins, boxes and outlines through both paths. OpenType explicitly permits this difference. [OpenType horizontal metrics](https://learn.microsoft.com/en-us/typography/opentype/spec/hmtx)

5. **missing-in-scope:** **Composite metric inheritance is absent.** `expand_composite()` does not interpret `USE_MY_METRICS` (`src/pdf/font.cpp:729`), and `advance()` always takes the composite’s own `hmtx` width. A composite requesting its component’s metrics therefore gets the wrong advance. Add a fixture whose parent and designated component have different metrics, including nested inheritance. The flag applies to unhinted glyphs too. [OpenType composite glyphs](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf)

6. **missing-in-scope:** **Legal phantom-point attachments are rejected.** The anchor check accepts only stored contour points (`src/pdf/font.cpp:833`); phantom points are never constructed. A composite anchored to a component’s phantom point returns `DamagedFormat` despite being valid. Implement the required metric points and add independently calculated attachment tests. [OpenType composite glyphs](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf)

7. **present:** Typed factory, loader, reference and face failures; resource failures do not trigger fallback. Evidence: `src/pdf/font.cpp:116`, `PdfFont.LoaderFailuresAreTyped`. Successful fallback leaves no false damaged-font diagnostic.

8. **missing-in-scope:** **The DirectWrite route bypasses the promised pre-expansion limits.** Native table validation and component/depth counting run only after DirectWrite rejects loading (`src/pdf/font.cpp:1284`). Otherwise `outline()` calls `GetGlyphRunOutline` directly (`src/pdf/font.cpp:1182`). The sink limits collected output after DirectWrite has done expansion; it cannot enforce 4,096 component visits or depth 16 before that work. `HostileFontProgramsRefused` forces fallback, leaving the normal route untested. Enforce the contract on both routes and test hostile fonts without injected rejection.

9. **missing-in-scope:** **Malformed contour endpoints can amplify memory independently of the point budget.** `src/pdf/font.cpp:632` accepts equal successive endpoints. Repeated components can consequently append thousands of empty contour entries while contributing almost no points; `contour_ends` grows at `src/pdf/font.cpp:678` and `src/pdf/font.cpp:710`. Reject non-increasing endpoints and test a compact repeated-component font under ASan. OpenType requires increasing endpoint indices. [OpenType simple glyphs](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf)

10. **missing-in-scope:** **Regression coverage does not exercise several delivered branches.** The corpus generator’s composite writer uses word arguments and uniform scale (`scripts/build-corpus.py`, `_glyf_composite`); current geometry assertions do not cover byte arguments, independent x/y scales, asymmetric 2×2 transforms or scaled offsets. The refusal suite also lacks the explicitly promised `loca`-past-`glyf` case. Add exact geometry and error-code assertions for these branches alongside findings 4–9.

11. **missing-out-of-scope:** **Actual PDF-to-screen consumption and recovery remain downstream work.** Font extraction/mapping, interpreter placement, `OutlineOnly` replay, cancellation and tile failure handling are owned by domain **01-engine**, principally T02 §§4, 6, 7, 19, 20 and 27–31. They need rendered PDF regressions and cancellation/error propagation before users receive this capability. These already have sections; do not create duplicates. Evidence: `todo/01-engine/TODO-02-actor-and-render.md:197`, `:278`, `:285`.

Controls, shortcuts, command-box entries, dialogs, settings, undo and persistence are not independent requirements of this read-only, in-memory API.
