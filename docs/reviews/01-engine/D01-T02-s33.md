**Part 1: completeness**

1. **present:** Indexed palettes, base-space conversion, index rounding/clamping and damaged-lookup recovery have implementation and regression coverage: `src/pdf/color.cpp:717`, `src/pdf/color.cpp:1314`, `PdfInterpreter.IndexedColors`.

3. **present:** The four function types, function arrays, clipping and common malformed-input refusals have coverage in `PdfInterpreter.Functions`. Calculator failures replace partial results with defined fallback values (`src/pdf/function.cpp:1202`); colour conversion records a diagnostic (`src/pdf/color.cpp:758`). This coverage does not resolve items 5 through 8.

4. **present:** Image-row conversion exposes the required interface, packed samples, `/Decode` handling and batched ICC conversion: `src/pdf/color.cpp:831`, `PdfColor.SpecialSpaceSamples`. This is component coverage, not proof that opening an image-containing PDF displays it correctly.

5. **missing-in-scope:** Correct cubic interpolation boundaries and coverage. `src/pdf/function.cpp:341` enables cubic interpolation for `/Size [3]`, although the specification requires ignoring `/Order 3` below four samples. The test at `tests/recto-tests/pdf_interpreter_tests.cpp:1545` incorrectly requires `0.6875` where linear interpolation gives `0.5`. Conversely, one-input tables above 65,536 samples silently become linear despite the contract promising cubic interpolation. Correct both boundaries and add conforming fixtures. [Adobe function specification](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf)

6. **missing-in-scope:** Continuous high-dimensional sampled conversion. The choice between multilinear and simplex interpolation depends on the number of *fractional coordinates*, not the function’s dimensionality (`src/pdf/function.cpp:727`, `src/pdf/function.cpp:747`). For the existing nine-input, all-ones-corner fixture, normalized output approaches `0.5` as the first coordinate approaches `1`, then becomes `0.00390625` at exactly `1`, with the other coordinates fixed at `0.5`. This produces abrupt colour changes. Add boundary-continuity regressions and use a consistent interpolation rule.

7. **missing-in-scope:** Full signed-integer semantics in calculator functions. Literal parsing, arithmetic classification and `cvi` exclude `-2147483648` through symmetric absolute-value checks (`src/pdf/function.cpp:508`, `:809`, `:894`). A valid `{ pop -2147483648 not }` transform should produce `2147483647`; this implementation classifies the literal as real and falls back after a type error. Test the signed endpoints through parsing, arithmetic, conversion and bitwise operations.

8. **missing-in-scope:** Aggregate memory protection for function trees and retained colour spaces. `ParseContext` counts nodes but not bytes (`src/pdf/function.cpp:158`); each sampled child independently permits 16 MiB (`:297`), and stitching reparses repeated references (`:640`). A small compressed PDF can request 255 copies of one 16 MiB table, almost 4 GiB, before accounting for spline storage. Colour-space retention adds another multiplication (`src/pdf/color.cpp:1032`). Add cumulative allocation budgets charged before allocation, with repeated-reference and compressed-table refusal tests. Catching allocation failure after exhausting memory is insufficient protection.

9. **missing-in-scope:** Evaluation without shared mutable state, as required by the Freeze check. Every evaluation updates a process-wide atomic test counter (`src/pdf/function.cpp:22`, `:1261`). Remove production instrumentation from this path or isolate it to test builds; verify concurrent evaluation without shared writes.

10. **missing-out-of-scope:** End-to-end text, image, stencil and Form rendering using these conversions, including `/None`. Inline images are still skipped (`src/pdf/interpreter.cpp:440`). Domain **01**, existing **D01 T02 §4**, already owns this integration; no duplicate section is needed. Completion requires PDF-to-DisplayList and rendered-image regressions, not only row-conversion tests.

Controls, shortcuts, command-box entries, dialogs, settings, undo, persistence and write-related disk/permission failures introduce no additional requirements here: this section has `Surface: no` and performs read-only conversion. The file’s Adjacency declaration assigns UI presentation elsewhere.
