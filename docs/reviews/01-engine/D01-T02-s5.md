4. **P2, lines 269 and 273: object-number allocation has no collision contract.** `set_object` accepts recorded new numbers, while `allocate_object` starts at the same base `/Size`; the xref stream also needs a number. Require allocation to skip every reserved number, reserve the xref-stream number through the same mechanism, and derive `/Size` from the final allocation state. Test interleaved explicit-number insertion and allocation, with references to every object verified after reopening.

Adobe’s [cross-reference specification](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.5_v6.pdf) describes these linked-list requirements.

6. **P2, lines 272 and 274: deterministic identifiers conflict with randomized encryption.** Hashing the emitted object bytes cannot give the same identifier for the same edit on AES documents: the shipped encryption API generates fresh random IVs. Define whether identifier determinism uses canonical plaintext changes before encryption or applies only to unencrypted revisions. Add a repeated AES-revision test that verifies the chosen identifier contract while retaining fresh IVs.
