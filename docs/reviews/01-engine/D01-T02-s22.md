## Decision table

Each name a TODO contract used that `src/pdf/error.h` did not have, the files that used it, the code it becomes and why. An existing code is chosen whenever the caller acts the same way; a code is appended only where a caller must act differently.

## Self-review

- Freeze check (`TODO-02` is `frozen: true`): `ConversionFailed` and `RollbackIncomplete` are appended after `InvalidArgument`, so every existing value is unchanged (`static_assert(static_cast<uint32_t>(ErrorCode::InvalidArgument) == 18u)` and the by-value name table in `PdfError.ErrorCodeNamesCoverEveryCode`); no state and no threading change; `error_code_name` stays `constexpr noexcept`.
- Recording decision (default, cost of reversing): neither new code records itself; the caller records it with the failed rule or the backup paths, which only it knows (`PdfError.ConversionAndRollbackCodesRecordOnlyWhenLogged`). Reversing is one `case` line in `should_auto_record_diagnostic`. A damage-sounding message never reclassifies either code (`classify_diagnostic_id`).
- No other switch over `ErrorCode` exists outside `error.h`/`error.cpp` (searched `src/` and `tests/`).
