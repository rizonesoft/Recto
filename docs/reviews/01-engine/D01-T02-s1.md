Check arithmetic and limits before allocation. Add limit-boundary, overflow and allocation-failure tests.

2. **P1, plan, lines 57, 72–74: Recorded data has no validation contract.** Specify valid path verb sequences and coordinate counts, pool index/range checks, matching glyph/origin counts, finite geometry and transforms, valid enum values, and bitmap dimension/stride/buffer-length checks using overflow-safe arithmetic. Define handling of unmatched saves/restores and invalid resource references. Test malformed records and padded bitmap rows; zero-copy sharing alone does not prove safe replay.

3. **P1, plan, lines 58, 74: “Exact ink bounding box” is underspecified and can produce destructive crop results.** Require transformed curve extrema, stroke caps/joins/miters/dashes, glyph outlines, nested Type 3 content, image transparency and actual clip geometry, rather than intersecting bounding rectangles. Define invisible and clip-only text, zero alpha, empty pages and fully clipped content. Address device-dependent hairlines explicitly. Add numerical fixtures that would fail for underestimated strokes, clipping holes and rotated/sheared content; the consumer’s 12 pt padding cannot repair arbitrary underestimation.

4. **P1, plan, line 74: Page geometry and crop-consumer semantics are unresolved.** `page_box_pt` cannot be inferred from painted content. Specify its input, the page-point coordinate convention, nonzero page-box origins, `/UserUnit`, and whether page rotation is already applied. Reconcile “all painted” bounds with `D05 T01 §4`, which excludes full-page white background fills. Provide either distinct bounds or sufficient documented per-command geometry for that consumer. Test a blank page, white background with inset content, and shifted/rotated page boxes.

5. **P1, plan, line 57: Graphics-state soft masks cannot be represented.** An image’s `soft-mask` field does not express `/ExtGState /SMask` affecting subsequent paths and text. Add an immutable mask resource and set/clear/save/restore semantics, including its group, transform and alpha/luminosity interpretation, or explicitly assign that representation to a named section before consumers use it. Require recording and restoration tests for masked vector and text content.

6. **P1, plan, lines 57, 74: Text clipping lacks a recording contract.** `Tr` on individual glyph runs does not identify when accumulated text clipping becomes active. Define how modes 4–7 accumulate glyph outlines and apply their combined clip at the text-object boundary, with correct subsequent state restoration. Add multi-run tests that distinguish unioned text clipping from intersecting each glyph separately, and verify that invisible/clip-only runs contribute no painted bounds.

7. **P1, plan, lines 57, 68, 74: Glyph bounds depend on later font work without an earlier interface.** Section 1 must compute glyph ink bounds, but the font loader and Type 1/3 outlines arrive in §2. Define now the immutable owning font-resource interface or validated outline/bounds input that makes §1 independently implementable and testable. Specify one coordinate convention instead of “text/user space,” including how font size, origins, text matrix and CTM combine. Test overhanging glyphs and Type 3 transforms; advance rectangles are insufficient.

8. **P1, plan, lines 64, 71, 73, 76: Const access does not prove immutable ownership.** A `shared_ptr<const DecodedBitmap>` can still alias an object held through a mutable pointer. Require ownership transfer or defensive copying at publication, no retained writable aliases into pools, and owning immutable references for fonts and nested lists. Define append-after-finish and repeated-finish behavior. Test source mutation/destruction and builder destruction after sealing, then verify identical payloads from concurrent readers.

9. **P2, plan, line 57: Dash recording leaves valid and invalid PDF patterns indistinguishable.** Specify empty solid patterns, odd-length repetition, zero-length entries in otherwise positive patterns, phase handling, and rejection of negative or nonempty all-zero arrays. Preserve PDF user-space units through the later Direct2D conversion. Add tests for these cases, including bounded handling of large phases. ISO 32000-1 §8.4.3.6 requires nonnegative elements that are not all zero. [Specification](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf?from=20423&from_column=20423)

10. **P1, plan, lines 68–79: The acceptance gates can pass an incomplete implementation.** Compilation and absence of mutable methods do not prove command payload preservation; ASan success does not prove lock-free access or correct concurrent results. Explicitly register production and test files in the MSBuild projects, require the expected tests to execute, and assert every command’s stored payload, pool ranges, resource identity and state transitions. Concurrent readers must compare results with known expected content. Add the negative and geometry fixtures above to the checkpoint, rather than allowing a few happy-path tests under `PdfDisplayList.*` to establish completeness.
