## Findings

1. **major: Resource-category alias copies escape the aggregate memory budget** (`src/pdf/document.cpp:1658`)
   - **Evidence:** `parsed_resource_cat_obj_cache` stores owning `PdfValue` copies, deep-clones the terminal value for every alias hop in `cat_hop_refs`, does not consult `parsed_resource_cat_obj_cache` at intermediate hops, and does not charge cached category allocations against `total_retained_resources_bytes`.
   - **Required fix:** Share immutable `std::shared_ptr<const PdfValue>` category values across aliases, consult cached targets during resolution, and charge all retained cache storage before insertion. Add a regression with distinct category-alias chains converging on one payload, including an aggregate-budget boundary.

2. **major: Alias sharing depends on the fast scanner accepting the object's spelling** (`src/pdf/document.cpp:1730`, `src/pdf/document.cpp:3261`)
   - **Evidence:** `try_read_uncompressed_ref_alias` skips whitespace but not PDF `%` comments, falling back to `resolve_object_with_visited` which traverses the entire chain without consulting caches at intermediate hops and builds duplicate dictionaries/summaries even when the terminal hop is already cached.
   - **Required fix:** Put cache-aware step-by-step alias traversal in the shared resolver so comments and compressed objects preserve cache sharing, and add regressions with commented and compressed alias chains.

3. **medium: Cache keys discard generation numbers and can poison later resolution** (`src/pdf/document.cpp:1691`, `src/pdf/document.cpp:3230`)
   - **Evidence:** Resource, category, destination and action caches key by `obj_num` alone and bypass generation validation on cache hits, allowing a stale reference (`10 1 R`) to poison or alias a live reference (`10 0 R`).
   - **Required fix:** Preserve full indirect-reference identity (`obj_num` and `gen_num`) throughout cache lookup, alias scanning and alias insertion, and test stale-first and valid-first ordering.

4. **medium: Retrying authentication after structure-loading failure can report success with an incomplete document** (`src/pdf/document.cpp:957`)
   - **Evidence:** `authenticate` sets `description_.is_authenticated = true` before `load_document_structure()`. If structure loading fails, a subsequent `authenticate` call sees `was_authenticated == true`, skips structure loading and returns `true`.
   - **Required fix:** Track successful structure initialization separately and keep authentication/structure loading transactional so repeated `authenticate` calls cannot turn a structure error into success. Add an encrypted malformed-document regression test.
