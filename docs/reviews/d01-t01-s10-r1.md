**Findings**

1. **Major: action-chain checks can classify prohibited actions as active links.** At `src/pdf/document.cpp:2249`, traversal stops after 16 actions and returns `false`. At `src/pdf/document.cpp:2270`, `/Next` array elements are checked only for their immediate action names, without traversing their children. Chained URI actions also bypass URI-scheme validation.

   An independent ASan probe reproduced three cases:
   - `/GoTo` followed by an array element whose `/Next` contains `/Launch`.
   - `/GoTo` followed by `/URI (javascript:alert)`.
   - Seventeen `/GoTo` actions followed by `/Launch`.

   All returned `LinkKind::Internal`, `is_inert=false`, instead of `RefusedAction`, `is_inert=true`. No execution was observed, but the required refusal classification is broken. Traverse the complete action graph with bounded work, validate URI schemes at every node, and refuse chains whose safety cannot be established.

2. **Major: `/Resources` inheritance merges dictionaries instead of replacing the inherited value.** `src/pdf/document.cpp:1501` retains ancestor categories and resource entries when a descendant supplies its own dictionary. The probe confirmed that a page with explicit `/Resources << >>` still exposes an ancestor's font.

   PDF inheritance applies when the attribute is omitted; an explicit resource dictionary overrides the inherited value. See ISO 32000-1, section 7.7.3.4. This produces incorrect effective resources and font inventories. `tests/recto-tests/pdf_document_tests.cpp:285` currently asserts the incorrect merge behavior. Correct both the resolver and that expectation, adding explicit-empty and replacement regression cases.
