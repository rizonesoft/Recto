## source-defect: needs-attention

2. **[P1] Literal scalars gain a nonexistent final newline.** `tests/scripts/test_issue_forms.py:215`: `load_yaml("a: |\n  text")` returns `{'a': 'text\n'}`; PyYAML returns `{'a': 'text'}`. `splitlines()` loses the termination information and the return unconditionally appends a newline. YAML clipping preserves an existing final break; EOF does not supply one. [Block chomping rules](https://yaml.org/spec/1.2.2/#8112-block-chomping-indicator)

3. **[P1] Accepted Unicode separators are rewritten inside literal scalars.** `tests/scripts/test_issue_forms.py:99` and `:215`: `load_yaml("a: |\n  text\u2028  next\n")` returns `'text\nnext\n'`, while PyYAML preserves `'text\u2028next\n'`. U+2029 reproduces the same mismatch. The printable-character check admits these characters, but `splitlines()` and newline joining cannot preserve their semantics. Refuse them or handle them explicitly. YAML 1.2 also treats these as content rather than ASCII line breaks. [Line-break rules](https://yaml.org/spec/1.2.2/#54-line-break-characters)
