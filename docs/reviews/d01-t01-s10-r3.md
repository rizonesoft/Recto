## Findings

1. **`major` — Page-tree `/Kids` expansion copies inherited `/Resources` for every queued sibling before cycle detection (`src/pdf/document.cpp`):**
   - In the `/Pages` tree walker, pushing all `/Kids` entries onto `page_stack` copied `current_attrs` (including the `PdfDict resources` by value) for every sibling before running visited-object cycle checks on those children. A hostile `/Pages` node with 4,096 repeated page references and a 64 KiB inherited `/Resources` dictionary reached 380 MB peak working set before returning the cycle error.
   - **Resolution:** Changed `InheritedPageAttrs::resources` (`src/pdf/document.cpp`) and `ResolvedPageRecord::resources` (`src/pdf/document.h`) to `std::shared_ptr<const PdfDict>` so inherited `/Resources` dictionaries are shared without copying, replaced the sibling-pushing `page_stack` with a cursor-based DFS stack (`ActivePagesFrame`, max 64 frames deep) that steps one child at a time (`0 .. N-1`) without duplicating sibling `PdfValue`s or `InheritedPageAttrs`, and checked `visited_page_nodes` across all indirect reference alias hops (`resolve_object_with_visited`) immediately as each child is visited. Added step 5 in `PdfDocument.PageTreeAndRotatedPages` (`tests/recto-tests/pdf_document_tests.cpp`) testing both 4,096 repeated `3 0 R` references and 4,096 indirect aliases (`20 0 R .. 4115 0 R -> 3 0 R`) with a 64 KiB inherited `/Resources` payload, asserting `ErrorCode::DamagedFormat` on `object_num == 3` and `< 32 MiB` working-set delta.
