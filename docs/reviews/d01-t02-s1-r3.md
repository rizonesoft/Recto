## Remaining and new findings

### R3-1: P1, accepted tiny dash values cause an infinite loop

Location: `src/pdf/display_list.cpp:833` (also dash expansion at line 2464).

`set_stroke_style()` accepts positive finite `[1e-13f, 1e-13f]`. The initial `while (pat_rem <= 1e-12)` then cycles forever because every entry satisfies the condition. An independent ASan-linked probe with `max_geometry_work_ops = 1` entered `draw_path()` and had to be terminated after three seconds. The loop has no budget check. More generally, generating every dash piece before charging work allows very small positive patterns to allocate enormous numbers of pieces.

Concrete fix: preserve positive dash lengths rather than treating them as zero, bound traversal through actual zero entries, and pass a checked work/allocation budget through dash expansion. Charge before each iteration and piece allocation; ensure floating-point progress or return a typed failure. Add timeout-bounded regressions for all-positive sub-epsilon patterns and small patterns exhausting the work budget.

### R3-2: P2, resource checks still occur after substantial allocations

Locations: `src/pdf/display_list.cpp:1290`, `2311`, `2935`, `3124`.

`current_pool_bytes()` uses vector sizes, ignoring retained reserved capacities. `push_clip_path()` builds reference edges, subdivided subpaths and the complete region before checking its bytes. Glyph rectangles are reserved before checking `max_glyphs` or total bytes. Image coverage constructs potentially one rectangle per opaque pixel without a scratch-byte reservation. These allocations can exceed a configured small budget before rejection. Curve splitting, mask scanning and active-span matching also do work not covered by the current charges.

Concrete fix: account for actual retained capacities and peak concurrent scratch ownership, including reservations and shared-resource ownership under an explicit policy. Thread one checked budget through geometry and coverage producers, charge before allocating/iterating, and validate glyph limits before reserving. Add small-budget tests with subdivided clips, saved states, checkerboard images and command pre-reservation. Static source finding; existing clip-depth and scanbeam tests do not exercise these allocation paths.

### R3-3: P2, curved clips still discard real ink

Location: `src/pdf/display_list.cpp:2311` and `2332`.

Install the closed cubic `(0,0), (0,100), (100,100), (100,0)` as the clip, then fill `[11.19999,49.45722,11.2,49.45723]`. This rectangle lies below the true cubic boundary and inside the clip, but the candidate returns success with `has_content_bounds() == false`. A larger rectangle `[10.5,0,11.2,100]` returns `y_max = 49.4571618164`, versus the true boundary approximately `49.4572565`. Clip installation samples the curve before future painted geometry is known and retains only chords, so the new curve/edge root finder cannot recover the lost boundary.

Concrete fix: retain analytic curve primitives in clip regions and solve intersections/extrema against subsequent painted geometry, including curved clips on either side of the intersection. Do not label fixed-tolerance polygon substitution exact. Add the reversed-role cubic test and the fully lost sliver regression.

### R3-4: P2, the initial zero-length painted dash is omitted

Location: `src/pdf/display_list.cpp:832`.

For line `(10,10)` to `(35,10)`, dash `[0,10]`, width `2` and round caps, the candidate reports `[19,9,31,11]`. The initial painted dot at `(10,10)` is skipped, so the correct left extent `9` is lost. The initial loop says it skips off-phase entries but actually skips zero-length on entries too; later on entries do produce dots.

Concrete fix: handle initial and subsequent zero-length on entries with the same cap-aware dash transition logic, preserving the start dot and checking the budget. Add zero-phase and exact-boundary-phase tests with round caps.

### R3-5: P2, run-level fallback retains the inter-glyph gap defect

Location: `src/pdf/display_list.cpp:2954` to `2964`.

Two glyphs at `(10,50)` and `(80,50)`, with no individual ink rectangles and a supplied run box `[10,50,90,62]`, remain accepted. With the clip `[35,0,65,100]`, the candidate reports ink `[35,50,65,62]` in the gap. The new test covers only callers supplying individual glyph rectangles; the fallback still uses the union as painted geometry.

Concrete fix: require per-glyph ink/outline information for visible runs, resolve it from the font resource, or reject insufficient geometry. A run box can remain metadata but cannot establish coverage inside the run. Add the same gap regression through the run-level fallback API.

### R3-6: P2, differing soft-mask dimensions expand coverage to transparent areas

Location: `src/pdf/display_list.cpp:1883` to `1907`.

A fully opaque `1x1` image and a `2x1` mask with alpha `[0,255]`, mapped to `[0,0,100,100]` with interpolation disabled, produce bounds `[0,0,100,100]`. Only the right half is visible, so the expected x range is `[50,100]`. The helper returns a Boolean for any overlapping opaque mask pixel and then emits the entire source pixel rectangle.

Concrete fix: intersect source and mask coverage in their common unit-image coordinate space, retaining mask-cell boundaries. Define and apply the same interpolation coverage rules as replay. Add different-resolution mask and clip-in-transparent-half regressions.
