# Review findings: D06 T05 §38 DCT decodes only the pixel representation the caller asked for

- Candidate: the implementation commit named below.
- Implementer: Claude (Opus 5.5), attended campaign run 2026-10-23.

## Self-review (implementing session, before the completion review)

- Failure modes named for this area (`AGENTS.md`): unbounded allocation on hostile input, and a stride or layout assumed. `decode_dct_image` takes a `DctOutput` (all three buffers, samples, RGBA, BGRA, or `Stream`, what DCTDecode returns as a filter) and builds only that; the samples are always decoded first and released afterwards when not asked for. The ceiling is charged with the peak of what is built (samples plus the 8-bit layouts asked for), so `Stream` on an RGB photo charges 3 bytes per pixel instead of 11.
- `decode_dct` asks for `Stream`, which reads a direct caller's `/TargetFormat` for a CMYK image exactly as before (RGBA by default, BGRA, or the CMYK samples); a stream dictionary's `/TargetFormat` is still dropped earlier (`PdfFilters.DocumentCannotSetTargetFormat` passes unchanged).
- `PdfFilters.DctLargePhotoWithinCeiling` encodes a 6000 x 4500 baseline JPEG with WIC's own encoder, decodes it through `decode_stream` at the default ceiling, and holds the heap meter's peak under one buffer plus 10 percent; with `decode_dct` asking for all three buffers it is refused (`DCTDecode cumulative decoded image buffers exceed ceiling`), as before this section.
- Decision taken (default, cost of reversing): `decode_dct_image` keeps `All` as its default, so existing direct callers and tests that read every buffer are unchanged; the stream filter is the path that asks for one. Reversing the default is a parameter change.

Part 1: completeness

Evidence below refers to commit `f83e183`, inspected with `git show`, not the later working tree. This is a static review; I did not run binaries or modify files.

1. **present:** The RGB stream-filter path requests `DctOutput::Stream` and moves the selected vector to its caller (`src/pdf/filters.cpp:6886`). `PdfFilters.DctLargePhotoWithinCeiling` checks that the 6000 × 4500 JPEG returns 81,000,000 sample bytes under the default ceiling (`tests/recto-tests/pdf_filters_tests.cpp:4905`).

2. **missing-in-scope:** RGBA and BGRA requests still build two image-sized buffers simultaneously. Samples are allocated first, the requested layout is allocated in `finish`, and samples are released afterwards (`src/pdf/filters.cpp:6732`, `6741`, `6768`, `6820`). The RGB photo therefore peaks at 189,000,000 Recto pixel-buffer bytes for RGBA, rather than 108,000,000. CMYK layout requests similarly retain samples alongside the layout. This violates §38’s “a decode allocates one image-sized buffer” contract.

3. **missing-in-scope:** Both early dimension guards charge four bytes per pixel regardless of the requested representation (`src/pdf/filters.cpp:6529`, `6689`). An 8 × 8 RGB sample request with a 192-byte ceiling is refused because those guards require 256 bytes, despite its only required buffer fitting exactly. Gray samples are overcharged further. These guards must use the representation’s actual requirements while preserving overflow and hostile-input protection.

4. **present:** Malformed JPEG input returns `DamagedFormat`: invalid SOI, truncated or invalid segment lengths, malformed SOF, missing SOF, and invalid dimensions/components (`src/pdf/filters.cpp:6454`, `6481`, `6488`, `6508`, `6519`, `6544`). WIC’s successful-but-empty decoder/frame and zero-size results also return `DamagedFormat` (`6661`, `6671`, `6682`). `PdfFilters.CorpusImageSeedsDecode` includes rejection of a damaged DCT seed (`tests/recto-tests/pdf_filters_tests.cpp:857`).

5. **present:** Header, frame and cumulative-buffer refusals return `DecompressionLimitExceeded`, distinct from actual allocation failure (`src/pdf/filters.cpp:6530`, `6690`, `6735`). Existing oversized-header and small-ceiling assertions cover refusals (`tests/recto-tests/pdf_filters_tests.cpp:4108`, `4118`), but do not catch item 3.

6. **present:** WIC failures retain typed returns: `OutOfMemory`, `Cancelled`, `UnsupportedFeature`, `DamagedFormat` or `InternalError`, according to HRESULT class (`src/pdf/filters.cpp:6357`). `PdfFilters.WicFailureClasses` exercises these returns (`tests/recto-tests/pdf_filters_tests.cpp:4936`). Their classification belongs to §37 and is not a gap here.

7. **present:** C++ allocation failure returns `OutOfMemory`; other caught exceptions return `InternalError` (`src/pdf/filters.cpp:6870`). Generic error-carrier tests exist in `pdf_error_tests.cpp`; the new §38 test does not inject failure into these DCT allocations.

8. **present:** Existing code-name, diagnostic-name, default-diagnostic and generic-message mappings cover all six relevant error codes (`src/pdf/error.h:51`, `141`, `252`, `295`). `PdfError.ErrorCodeNamesCoverEveryCode` checks enumeration coverage (`tests/recto-tests/pdf_error_tests.cpp:445`). This feature adds no new error code requiring another mapping row.

9. **missing-in-scope:** Regression coverage does not prove the requested-buffer contract across representations. The heap assertion measures only the RGB stream decode; the RGBA assertion checks returned vectors after temporary samples have been freed (`tests/recto-tests/pdf_filters_tests.cpp:4915`, `4925`). Add independently measured Samples/RGBA/BGRA/Stream cases for RGB, gray and CMYK, including `/Decode`, channel order, alpha, exact-fit success and one-byte-under refusal. The memory assertion is disabled under ASan (`tests/recto-tests/test_support.h:171`), so a measuring non-ASan run is also required.

10. **missing-out-of-scope:** DCT ceiling refusals lack actionable structured diagnostic context and are not recorded by the direct/filter paths shown. `make_filter_error` discards its diagnostic argument and constructs an unrecorded `PdfError` (`src/pdf/filters.cpp:43`); the refusal carries neither required bytes nor bound (`6735`). The ring and ETW schema can carry numeric refusal context (`src/pdf/error.cpp:901`, `984`), but these DCT paths do not populate it. Owner: **01-engine**, with **06-quality** regression coverage. Required tests should force each DCT refusal and verify one record containing cause, representation, required bytes and ceiling, without document content.

11. **missing-out-of-scope:** CLI error consumption, explicit exit-code mappings, stderr and JSON are not delivered: `src/cli/main.cpp:9` only prints scaffold information and returns success. Owner: **01-engine, D01 T03 §1**, which already requires a complete exit-code table and `Cli.ExitCodeTableCoversEveryCode`. Add DCT success/refusal integration cases preserving the typed cause and numeric context.

12. **missing-out-of-scope:** User-facing recovery and support delivery remain unimplemented. The planned could-not-open wording calls a file damaged or non-PDF (`todo/02-viewer/TODO-01-app-shell.md:407`), which cannot describe a valid JPEG refused by a memory ceiling. Owner: **02-viewer** for cause-specific messages and copyable details; **07-release** for report/bundle consumers (`D07 T03 §2`, `D07 T02 §4`). Required tests must distinguish configured refusal, actual OOM, damage, unsupported capability, cancellation and internal failure, and verify privacy-safe copied/exported diagnostics.
