## Self-review (implementing session, before the completion review)

- Failure modes named for this area (`AGENTS.md`): a malformed-input failure reported as success, and unbounded work on hostile input. One routine, `recover_damaged_row`, serves both Group 3 paths: it applies only with `/EndOfLine true` and `K` non-negative (Table 11), finds the damaged row's end at the next EOL (a bounded forward scan, one pass over the remaining bits), and substitutes the previous row if that row was good or a white row if it was damaged too, up to `/DamagedRowsBeforeError` rows in a row; past that, or without an EOL to resynchronize at, the stream is refused as before.
- Mixed Group 3 (`K > 0`) now recovers from a corrupt row and from a missing EOL at a row's start (the previous row ran past its end), honouring each row's tag bit after resynchronizing; a good row resets the count, as in pure Group 3.
- Behaviour change: pure Group 3 used to recover without `/EndOfLine true`, which Table 11 does not allow (there is no EOL to find a row's end); it is refused now. `PdfFilters.CcittDamagedRowRecovery` covers both `K = 0` and `K = 2` (the good row once, then white), one row over the limit refused, and no recovery without `/EndOfLine`.
