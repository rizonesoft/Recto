# Review - D06 T05 §27: ARM64 Debug build free of the CS1668 LIB search-path warnings

- **Section:** `D06 T05 §27` (`todo/06-quality/TODO-05-stamp-audits.md`)
- **Date:** 2026-10-22

## What logs the warnings

- **Task:** three inline MSBuild tasks, `GetGlobalProperties`, `GetVcpkgEnvVars` and `RestoreEnvVars`, each declared with `TaskFactory="RoslynCodeTaskFactory"`, which compiles its C# with `csc` (logged as `ROSLYNCODETASKFACTORYCSHARPCOMPILER`).
- **Declared in:** Visual Studio's bundled vcpkg, `C:\Program Files\Microsoft Visual Studio\18\Professional\VC\vcpkg\scripts\buildsystems\msbuild\support\GetGlobalProperties.task`, `GetVcpkgEnvVars.task` and `RestoreEnvVars.task`, used by `vcpkg.targets`' install step (`VcpkgInstallImplementation`). They compile only when that step runs (its stamp, `vcpkg_installed\arm64-windows\.msbuildstamp-arm64-windows.stamp`, older than its inputs) and a node has not compiled them yet, which is why an up-to-date build was silent.
- **`LIB` they see:** `SetBuildDefaultEnvironmentVariables` (`Microsoft.Cpp.Current.targets`) sets `LIB` to `$(LibraryPath)`. For `recto-tests` ARM64 Debug that was `VC\Tools\MSVC\14.51.36231\lib\ARM64`, `VC\Tools\MSVC\14.51.36231\atlmfc\lib\ARM64` (absent), `Windows Kits\10\lib\10.0.26100.0\ucrt\arm64`, `VC\Auxiliary\VS\UnitTest\lib`, `Windows Kits\10\lib\10.0.26100.0\um\arm64` and `Windows Kits\NETFXSDK\4.8\lib\um\arm64` (absent). On x64 every entry exists, so x64 never warned.

## Fix

- `Directory.Build.targets`: `RectoKeepExistingLibraryPaths` runs through `SetBuildDefaultEnvironmentVariablesDependsOn` (the toolset's extension point) just before `LIB` is set, and keeps only the `LibraryPath` folders that exist. Recto links neither ATL/MFC nor .NET Framework libraries, so the folders it drops were never used. Nothing is suppressed: CS1668 is not disabled and no log is filtered.
- `build/build.ps1`: after each configuration, `Assert-NoMSBuildWarnings` (`build/msbuild-log.ps1`) fails the run when MSBuild's log summary reports any warning, from any tool, or has no summary.

## Proof

Each run back-dated the ARM64 vcpkg stamp and ended idle MSBuild nodes, so the inline tasks compiled again:

- Before the fix (`build.ps1 -Platform ARM64 -Configuration Debug -SkipTests`): 4 `CS1668` warnings, exit 0.
- With the warning check and without the `Directory.Build.targets` fix: exit 1, `build has 4 warning(s): Debug|ARM64`.
- With both: `VcpkgInstallImplementation` ran, no `CS1668`, exit 0.
- `python -m unittest tests.scripts.test_build_ps1` -> `Ran 8 tests`, `OK` (a clean log passes; a tool warning and a log without a summary fail).

## Checkpoint

`.\build.cmd` -> exit 0; `0 Warning(s)` for Debug|x64, Release|x64, Debug|ARM64 and Release|ARM64 (the new check passed on each); `[  PASSED  ] 103 tests.` for Debug|x64 and Release|x64. CI's latest main build (run `39714460205`) logs `0 Warning(s)` in every configuration, so the check holds there too.
