## Findings

1. **`major` — Named destinations retain full `PdfValue` dictionaries per name, amplifying allocation (`src/pdf/document.h`, `src/pdf/document.cpp`):**
   - In `load_document_structure()`, `named_dests_` stored `std::unordered_map<std::string, PdfValue>` and resolved each destination value separately even when many destination names referenced a shared 64 KiB dictionary.
   - **Resolution:** Changed `named_dests_` to `std::unordered_map<std::string, ParsedDest>` (`sizeof(ParsedDest) == 56` bytes), parsed each destination array or `<< /D [...] >>` dictionary into a lightweight `ParsedDest` struct immediately during collection, and cached indirect destination objects in `std::unordered_map<uint32_t, ParsedDest>` across alias hops so shared destination objects are resolved at most once. Also bounded destination name length (`kMaxDestNameBytes = 4096`) and aggregate retained name bytes (`kMaxTotalNamedDestBytes = 4 MiB`). Added a regression in `PdfDocument.OutlinesAndNamedDests` (`tests/recto-tests/pdf_document_tests.cpp`) testing 2,048 destination names sharing a 64 KiB destination dictionary and asserting `< 32 MiB` working-set delta.

2. **`medium` — Per-page `/Annots` limit (1,024) and `/Resources` dictionary entry limit (1,024) silently drop valid links or fonts (`src/pdf/document.cpp`):**
   - Stopping `/Annots` traversal at 1,024 entries without returning an error caused a page with 1,025 distinct link annotations to silently drop the 1,025th link, and `/Resources /Font` / `/XObject` loops had the same 1,024-entry silent truncation.
   - **Resolution:** Removed the silent 1,024 truncation in `/Annots` and `/Resources` font/XObject scanning while preserving indirect-object cycle/alias deduplication (`visited_page_annots`, `visited_font_objs`, `visited_xobj_objs`) and returning a typed `ErrorCode::DamagedFormat` error if a page's `/Annots` array exceeds `kMaxAnnotsPerPage` (`65,536`). Added a regression in `PdfDocument.LinksAndRefusedActions` verifying 1,025 distinct `/Subtype /Link` annotations are all extracted without silent loss.

3. **`medium` — `parse_iso8601_date` is marked `noexcept` while calling `dt.raw.assign()` and `dt.to_iso8601()` (`src/pdf/document.cpp`):**
   - If `dt.raw.assign()` or `dt.to_iso8601()` throws `std::bad_alloc` inside `parse_iso8601_date(...) noexcept`, the C++ runtime invokes `std::terminate` before the outer `try`/`catch` in `parse_pdf_date(...) noexcept` can catch it.
   - **Resolution:** Removed `noexcept` from `parse_iso8601_date` so any allocation exception propagates into `parse_pdf_date`'s `try`/`catch (...)` block and safely returns `std::nullopt`. Added allocation-failure fault-injection coverage in `PdfDocument.Metadata` (`tests/recto-tests/pdf_document_tests.cpp`) testing `parse_pdf_date` on both `D:YYYY...` and ISO-8601 XMP date strings under `ScopedAllocFailAfter`.
