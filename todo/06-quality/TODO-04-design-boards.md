# TODO-04 -- Design Boards and SPEC Text for Undesigned Screens

> **Goal:** Every screen, panel, bar and dialog the plan builds has a numbered `design/SPEC.md` subsection that names its controls and a generated `design/screenshots/D-<Name>.png` board drawn from a `design/mockups/source/D-<Name>.dc.html` canvas source under SPEC sections 3 to 7 (Fluent UI System Icons from `RectoIcons`, no icon tiles, the 4, 8 and pill radius system, token colours only), each ready before the first section that builds the surface, and one script proves a board is rendered, cited and complete.

## 1. Board check script and single-board render option

Every board section below ends with the same falsifiable proof, so the proof is built once: a stdlib Python check that a board is rendered at its canvas size and is not blank, cited by its SPEC subsection, complete against the controls its consumer sections name, drawn with every listed control visible on the rendered board, styled with token colours and the SPEC section 7 radii on the right element roles only (no icon tiles), and cited back by every consumer. Completeness is measured against an inventory the manifest does not author: the check reads each consumer section's own text, so a control a consumer names that the manifest, the SPEC subsection or the rendered board omits fails. Shape and colour are measured on the rendered page, not on source literals alone, so a style supplied through `renderVals()` data or as `rgb()` cannot slip past. `render-mockups.mjs` today rewrites every board on each run, which churns unrelated PNGs; a `--only` filter lets a section render its own board.

**Phase:** 2
**Needs:** windows-host
**Surface:** no

Add `--only <name>[,<name>]` to `design/tools/render-mockups.mjs`: render only the named sources (name without `.dc.html`), exit 1 listing the known boards when a name has no source or no `canvas.json` entry, and keep the full run unchanged without the flag. For every board it renders it also writes the element inventory `design/mockups/html/<name>.elements.json`: a second headless pass (`--dump-dom`) loads the rendered HTML with an injected script that, for every element carrying `data-control`, `data-role` or `data-glyph` and every element whose computed `border-radius` is not `0px`, records the attributes, the bounding box, `display`, `visibility` and `opacity`, the computed `border-radius`, `color`, `background-color`, the four border colours, `outline-color`, `fill`, `stroke` and `box-shadow`, and an `svg` element's path data, serialised into a JSON `<script>` the tool extracts.
