4.2 Thread ownership rules, as Recto applies them

1. One owner per document. A parsed pdf::Document and its object cache belong to the one DocumentActor thread that opened it. No mutex sits inside the parser.

2. Jobs open their own copy. Conversion, OCR and authoring jobs open their own pdf::Document and never share the viewer's.

3. Pages are read once. The actor interprets a page's content stream once, on its own thread.

4. Display lists are the hand-off. The actor builds an immutable DisplayList for a page. Once built, a display list is read-only and can be rasterized by many RenderPool workers at the same time. This is how rendering runs in parallel while the document stays single-threaded.

5. Workers abort cooperatively. Each worker checks its CancelToken between command batches, and a tile from an aborted render is never cached.

6. Errors are values. Malformed objects, truncated streams and bad passwords return PdfResult with a PdfError. Nothing throws across a boundary.

7. Shutdown runs in order. Every DocumentActor and RenderPool worker is joined before the Runtime shuts down.
