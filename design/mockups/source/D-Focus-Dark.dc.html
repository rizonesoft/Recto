4.3 Runtime and Thread Map

Recto creates one recto::core::Runtime at startup and destroys it after all documents, views, and jobs have closed.

4.4 Opening a Document and Recording Display Lists

1. UI thread calls Runtime::open(path), which spawns a DocumentActor thread for that tab and returns a lightweight DocumentHandle.

2. On the actor thread, Recto parses the header, trailer, and XRef table or stream. If the document is encrypted and the empty user password does not authenticate, the actor posts NeedsPassword to the UI thread.

3. Immediately after DocumentOpened, the UI can size the scroll canvas and draw page outlines.

4. When the viewport needs page p, the TileScheduler asks the actor for DisplayList(p). The actor interprets the page's content stream into an immutable DisplayList and hands it to the RenderPool.
