4.2 MuPDF's rules, as Recto applies them

1. Locks first. The base context is created with a lock table of FZ_LOCK_MAX locks. Without it, cloning a context is not allowed and nothing below is safe.

2. One context per thread. Every thread that calls MuPDF has its own fz_context, made with fz_clone_context(base) at thread start.

3. A document belongs to one thread. An fz_document and every fz_page loaded from it are used only on that document's actor thread.

4. Display lists are the hand-off. The actor builds an fz_display_list for a page. Once built, a display list is read-only and can be rendered by many threads at the same time, each with its own context. This is how rendering runs in parallel while the document stays single-threaded.

5. Other objects move, but are never shared. A pixmap, buffer or stext page made on one thread may be passed to another, provided only one thread uses it at a time.

6. Reference counts are thread-safe; the objects are not. fz_keep and fz_drop may run on any thread with that thread's context.
